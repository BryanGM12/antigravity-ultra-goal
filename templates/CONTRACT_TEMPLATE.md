## 2. Criterios de Aceptación Empíricos (No Negociables)
Los siguientes criterios deben ser demostrables mediante ejecución de scripts o herramientas:
- [ ] **Compilación / Sintaxis:** Código compila o ejecuta sin errores (`exit code 0`).
- [ ] **Shell de Usuario & Entrada (Nivel 1):** Menú de inicio, navegación/CLI help completa y pantalla de ajustes funcionales.
- [ ] **Modelo de Dominio & Reglas (Nivel 2):** Entidades tipadas y lógica desacoplada de la vista (prohibido código hardcodeado para 1 solo caso).
- [ ] **Interacción & Reactividad (Nivel 3):** Drag-and-drop, filtrado en tiempo real y sincronización de estado verificada con mapas diferenciales.
- [ ] **Amplitud de Contenido (Nivel 4):** Catálogo representativo con mínimo 8 a 15 datos/materiales/componentes reales (Zero-Paucity Invariant).
- [ ] **Resiliencia & Error Boundaries (Nivel 5):** Cero bloques `catch` vacíos, reintentos con backoff y validación de entradas.
- [ ] **Rendimiento & Cero Fugas (Nivel 6):** Cero allocations en bucles de alta frecuencia, cancelación de listeners y tiempos < 100ms / 60 FPS estables.
- [ ] **Persistencia & Durabilidad (Nivel 7):** Persistencia confiable entre sesiones (LocalStorage/DB/JSON) con exportación/importación.
- [ ] **Cobertura de Pruebas:** Suites de tests automatizadas completas en verde (mínimo 95% de assertions exitosas).
- [ ] **Ausencia de Antipatrones:** 0 TODOs, 0 FIXMEs, 0 stubs (`NotImplemented`), 0 secretos expuestos.
